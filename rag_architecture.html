Project Overview

Custom GPT RAG Pipeline
on Snowflake

A Retrieval-Augmented Generation system that processes confidential documents into a Snowflake vector database, then exposes a FastAPI search endpoint consumed by a Custom ChatGPT.

System Architecture
01
ETL
📄
Source Documents
PDFs, DOCX, TXT, JSON, Excel files (your client confidential data)
🔪
Chunking
1500-char chunks, 100-char overlap via ETL_Code.ipynb
🧠
OpenAI Embeddings
text-embedding-3-small → 1536-dim float vectors
Outputs a CSV of chunks + metadata + vectors
02
Storage
❄️
Snowflake
Vector-native table storing text chunks + VECTOR(FLOAT, 1536) embeddings. Cosine similarity search built-in.
🌲
Pinecone (optional)
Alternative/additional vector store. Disabled by default in this setup.
Table created by Lucy's team (for your RAG). You'll get the TABLE_NAME.
03
API
🐙
GitHub Repo
Hosts app.py + requirements.txt. Source for Render deployment.
🚀
Render Web Service
Runs the FastAPI app. Env vars set here. Auto-deploys from GitHub.
⚡
FastAPI /query/
POST endpoint: takes query text → embeds it → cosine search on Snowflake → returns top-K chunks.
Public HTTPS endpoint for ChatGPT to call
04
GPT
🤖
Custom GPT (ChatGPT)
Configured with the Action Schema (OpenAPI spec). Calls /query/ with user's question, receives document context, generates grounded answer.

Can you set it up locally?

Partially. You can run the FastAPI app locally with uvicorn app:app --reload once you have Snowflake credentials and an OpenAI key. However, ChatGPT's Custom GPT Actions require a publicly accessible HTTPS URL — so for the full end-to-end flow you need Render (or an equivalent hosting service like ngrok for local testing). The ETL notebook is designed for Google Colab (it has a GPU accelerator setting) but will also run in a local Jupyter environment. Bottom line: you have all the code, but you are blocked on 3 external credentials before anything works end-to-end.
